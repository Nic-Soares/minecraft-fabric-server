Orçamento de memória

Cenário mais exigente: você joga no mesmo Mac que roda o servidor. O heap fica fixo em 6 GB; C2ME e ZGC gostam de folga, e sobra espaço para cache de arquivos do macOS.

06121824 GB
6 GB macOS, navegador, IDE
5 GB cliente Minecraft
6 GB heap do servidor
1,5 GB nativo da JVM (metaspace, code cache, buffers)
5,5 GB livre para page cache

Se o servidor rodar sozinho, suba para MC_HEAP=8G. Acima disso o ganho é nulo para poucos jogadores e o ZGC só varre mais memória.

Decisões técnicas

ZGC em vez de G1

Pausas abaixo de 1 ms. Uma pausa longa do GC aparece no jogo como travada. Custa um pouco mais de CPU, que o M5 tem de sobra.

Compact Object Headers

Recurso estável no JDK 25 (JEP 519). Cada objeto fica 4 bytes menor. Com milhões de objetos pequenos, sobra heap e o GC trabalha menos.

Heap fixo de 6 GB

-Xms igual a -Xmx e AlwaysPreTouch: a memória é reservada no boot, e não no meio do jogo. Troque com MC_HEAP=8G.

Mods só no servidor

O cliente entra com o 26.3 vanilla do launcher. Não precisa instalar Fabric no cliente.

launchd como supervisor

Reinicia em caso de crash e manda SIGTERM ao desligar; o servidor salva o mundo antes de sair. O plist fica no projeto, então o servidor não liga sozinho no login.

mods.txt + mods.lock

update escolhe as versões e grava o lock. sync instala só o que está no lock, com sha512. Qualquer máquina monta o mesmo servidor.

Fora da stack: Krypton (sem build para 26.3), VMP (só ajuda com dezenas de jogadores), ServerCore (muda o gameplay).

    • ARCHITETURE.html, GIT.md documentação

      • .env senhas, fora do Git

      • config/, whitelist.json, ops.json versionados
      • mods/ world/ logs/, *.jar fora do Git
